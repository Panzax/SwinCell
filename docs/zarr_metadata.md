# Zarr Metadata-Based Training

This document describes how to use the Zarr metadata-based data loader for training SwinCell models on synthetic and real zebrafish data.

## Overview

The Zarr metadata loader allows you to train models on 3D Zarr cube datasets indexed by metadata CSV files. This enables training one model on synthetic data and another on the corresponding real data, both using the same ROI locations.

## Single CSV Workflow (Recommended)

The recommended approach is to use a **single unified CSV file** (`training_metadata.csv`) that has been pre-processed and validated. This simplifies training and ensures metadata consistency.

### Preprocessing Step

Before training, you must generate `training_metadata.csv` using the preprocessing script:

```bash
python scripts/prepare_synthetic_metadata.py \
    --prepared_csv /path/to/prepared.csv \
    --tile_view_csv /path/to/prepared_tile_view_w_annotations_fixed.csv \
    --output_csv /clusterfs/nvme/segment_3d/databases/synthetic_data/training_metadata.csv \
    --check_paths
```

This script:
- Merges `prepared.csv` (high-level metadata) with `prepared_tile_view_w_annotations_fixed.csv` (tile-level metadata)
- Validates the merged data
- Creates a unified schema with all necessary columns
- Optionally checks that Zarr paths exist

The output `training_metadata.csv` contains:
- All geometry fields (`z_start`, `y_start`, `x_start`, `z_end`, `y_end`, `x_end`, sizes)
- Pre-computed paths (`synthetic_cube_path`, `real_cube_path`)
- Flags (`is_synthetic`, `exists`)
- All other metadata needed for training

### Training with Single CSV

When using the unified CSV, simply point `--metadata_root` to the CSV file:

```bash
python ./swincell/train_main.py \
    --use_zarr_metadata \
    --metadata_root=/clusterfs/nvme/segment_3d/databases/synthetic_data/training_metadata.csv \
    --use_synthetic \
    --dataset=zebrafish_memhistone \
    ...
```


## Requirements

- Metadata CSV files (see above)
- Zarr cube files organized according to the metadata paths
- Python packages: `zarr` or `tensorstore`, `pandas`, `numpy`

## Metadata Format

The `training_metadata.csv` file contains all necessary columns in one file:
- `prepared_id`: Unique identifier
- `tile_name`: Name of the Zarr cube file (e.g., `000x_000y_000z.zarr`)
- `output_folder`: Relative path to the ROI folder
- `server_folder`: Base path for synthetic data
- `data_location`: Base path for real data
- `z_start`, `y_start`, `x_start`: ROI start coordinates
- `z_end`, `y_end`, `x_end`: ROI end coordinates
- `z_size`, `y_size`, `x_size`: ROI dimensions
- `cube_size`: Size of the cube (typically 128)
- `time_size`: Number of time points (typically 1)
- `channel_size`: Number of channels (typically 2: image + mask)
- `is_synthetic`: Boolean indicating if this is synthetic data
- `synthetic_cube_path`: Pre-computed path to synthetic Zarr cube
- `real_cube_path`: Pre-computed path to real Zarr cube (may be NaN)

## Usage

### Command Line Arguments

When using the Zarr metadata loader, add these arguments:

- `--use_zarr_metadata`: Enable Zarr metadata-based loading
- `--metadata_root`: Path to `training_metadata.csv` (must be generated by `prepare_synthetic_metadata.py`)
- `--use_synthetic`: Use synthetic data (default: True). Set to False for real data
- `--dataset`: Dataset name (use `zebrafish_memhistone` or `zebrafish` for zebrafish data)
- `--max_rois`: Maximum number of ROIs to use (optional). Useful for large datasets. If not specified, all available ROIs are used.

### Example: Training on Synthetic Data

```bash
# First, generate the unified metadata CSV (one-time preprocessing step)
python scripts/prepare_synthetic_metadata.py \
    --prepared_csv /path/to/prepared.csv \
    --tile_view_csv /path/to/prepared_tile_view_w_annotations_fixed.csv \
    --output_csv /clusterfs/nvme/segment_3d/databases/synthetic_data/training_metadata.csv

# Then train using the unified CSV
python ./swincell/train_main.py \
    --use_zarr_metadata \
    --metadata_root=/clusterfs/nvme/segment_3d/databases/synthetic_data/training_metadata.csv \
    --use_synthetic \
    --dataset=zebrafish_memhistone \
    --model=swin \
    --logdir=./results/synthetic_zarr \
    --max_epochs=3000 \
    --batch_size=1 \
    --roi_x=96 \
    --roi_y=96 \
    --roi_z=32 \
    --use_flows \
    --save_checkpoint \
    --max_rois=1000
```

### Example: Training on Real Data

```bash
python ./swincell/train_main.py \
    --use_zarr_metadata \
    --metadata_root=/clusterfs/nvme/segment_3d/databases/synthetic_data/training_metadata.csv \
    --use_synthetic=False \
    --dataset=zebrafish_memhistone \
    --model=swin \
    --logdir=./results/real_zarr \
    --max_epochs=3000 \
    --batch_size=1 \
    --roi_x=96 \
    --roi_y=96 \
    --roi_z=32 \
    --use_flows \
    --save_checkpoint
```

## Zarr File Structure

The Zarr cubes are expected to be in petakit-style format with nested structure:
- Path: `{server_folder}/{output_folder}/{tile_name}/`
- Structure: `c/{time}/{channel}/{z}/{y}/{x}/` (nested chunks)
- Channels: Channel 0 = image, Channel 1 = mask/label

The loader automatically handles reading from this nested structure.

## Dataset Configuration

The zebrafish dataset configuration (`zebrafish_memhistone` or `zebrafish`) automatically:
- Uses `cube_size` from metadata (typically 128)
- Calculates image dimensions from ROI extents
- Applies appropriate resizing based on `downsample_factor`

## Training Scripts

Pre-configured training scripts are available:
- `train_synthetic_zarr.sh`: Train on synthetic data
- `train_real_zarr.sh`: Train on real data

Both scripts use the same ROI list, ensuring that synthetic[0] corresponds to real[0] for aligned training.

## Weights & Biases Logging

SwinCell supports Weights & Biases (Wandb) for experiment tracking and visualization.

### Enabling Wandb

Add the following arguments to enable Wandb logging:

- `--wandb_project`: Project name (required to enable Wandb)
- `--wandb_entity`: Entity/team name (optional)
- `--wandb_run_name`: Custom run name (optional, auto-generated if not provided)
- `--wandb_mode`: Logging mode - `online`, `offline`, or `disabled` (default: `online`)

### Example with Wandb

```bash
python ./swincell/train_main.py \
    --use_zarr_metadata \
    --metadata_root=/clusterfs/nvme/segment_3d/databases/synthetic_data/training_metadata.csv \
    --use_synthetic \
    --dataset=zebrafish_memhistone \
    --model=swin \
    --logdir=./results/synthetic_zarr \
    --wandb_project=swincell_zebrafish \
    --wandb_run_name=synthetic_experiment_v1 \
    --wandb_mode=online \
    --max_epochs=3000 \
    --use_flows \
    --save_checkpoint
```

### Logged Metrics

Wandb automatically logs:
- Training loss per epoch
- Validation Dice scores (mean and per-class)
- Learning rate
- Best validation Dice
- Training and validation images (if `--save_temp_img` is enabled)
- Model checkpoints as artifacts (best model only)

### Configuration

All hyperparameters are automatically logged to Wandb config, including:
- Model architecture and parameters
- Dataset configuration
- Optimizer settings
- ROI sizes and training parameters
- Zarr metadata settings (if using `--use_zarr_metadata`)

## Notes

- The loader filters to cubes only (not 2D tiles)
- Both synthetic and real cubes must exist for paired training
- The same ROI indices are used for both synthetic and real training to ensure alignment
- Default train/val split is 80/20, or use `--fold` for k-fold cross-validation
- Use `--max_rois` to limit the dataset size for faster iteration or testing (e.g., `--max_rois=1000` for first 1000 ROIs)
